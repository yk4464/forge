# forge — Rust 编程 Agent（Milestone 1 计划）

## 已确认的决策
- **定位**：编程/开发类 agent，解决自己真实需求；高性能、模块化、TUI 优先
- **技术栈**：Rust + Tokio + Serde + tracing；TUI 用 Ratatui + Crossterm；SQLite + SQLx（M1 即接入）；Agent 扩展体系（Skills/Hooks/MCP/Plugins）按 trait + registry + adapter 设计，具体实现后置
- **里程碑 1 = 核心循环 → TUI 跑通**：Provider + Tool registry + Agent Loop + AgentEvent + SQLite 会话 + TUI 对话
- **工具**：首发仅 1 个 `shell` 工具（执行命令打天下）；权限层架构留位（PermissionPolicy trait + registry），MVP 策略默认 allow 全放行
- **Provider**：首发实现 3 个协议面 — `/v1/chat/completions`（OpenAI-compatible，覆盖 DeepSeek/智谱/通义）、`/v1/responses`、`/v1/messages`（Anthropic 格式）；共用一套 trait
- **流式一等公民**：Provider trait 对话接口从第一天返回 `Stream<Item = ProviderEvent>`，三个协议面都实现 SSE 流式；reasoning（`reasoning_content`）作为独立 AgentEvent 流式显示 + 落库
- **Skill**：M1 不实现，`Skill` trait + registry 在 agent-core 中留占位
- **上下文管理**：清洁室复刻 Codex 机制（调研已完成，见下）
- **默认值（最后一轮未答复，可随时改）**：项目名 **forge**（crates: forge-core/forge-provider/forge-tools/forge-storage/forge-tui，二进制 `forge`）；TUI 四命令 `/new` `/resume` `/compact` `/exit`

依赖方向：tui → core → {provider, tools, storage}（core 只依赖 trait 定义所在处；provider/tools/storage 实现 core 的 trait）。

## 核心设计（调研结论直接落进实现）

### AgentEvent（core 定义，tui/storage 共同消费）
```
enum AgentEvent {
  TurnStarted, TurnCompleted { usage },
  MessageDelta { delta },                    // 正文流
  ReasoningDelta { delta },                  // 思维链流（独立事件）
  ToolCallStarted { call_id, command }, ToolCallOutputDelta { call_id, chunk },
  ToolCallCompleted { call_id, exit_code, duration },
  CompactionStarted, CompactionCompleted { tokens_before, tokens_after },
  Error { message }, TokenCountUpdated { used, limit },
}
```
core 通过 `tokio::sync::mpsc` 广播；TUI 渲染、storage 异步落库各自订阅。

### Agent Loop（forge-core）
轮内循环：发请求（流式）→ 边收边发事件 → 收到 tool_call → 执行 shell → 结果回填 → 继续；每轮工具输出入账后做阈值检查（规避 Codex #16033 轮间不检查 bug）。

### 上下文管理（抄 Codex，规避其 4 个坑）
- token 估算：字节启发式 `ceil(bytes/4)`；真实 usage 来自 API 响应 usage 字段，运行估计 = last usage + 其后新增项的字节估计
- 阈值：`min(配置值, floor(窗口 × 0.90))`，基于有效窗口推导（规避 #40095 的 94.7% 错位）
- 触发点：pre-turn + 每次工具输出入账后（规避 #16033）
- 压缩（本地路径）：摘要 prompt 作为 user 消息发普通请求 → 取最后一条 assistant 消息 + SUMMARY_PREFIX 组成摘要；新历史 = 最近 user 消息（预算 20k token，从新到旧贪心，放不下截断后停）+ 末尾摘要；收集时跳过旧摘要消息；发 Warning 事件
- 摘要请求自身爆窗：从最旧条目删起（连带配对 tool 输出）重试
- 工具输出截断：写入历史时按字节预算头尾各半保留，中间插 `…N chars truncated…`
- 记账用独立字段，不覆写累计值（规避 fill_to_context_window 突变坑）

### shell 工具（forge-tools，唯一工具）
- Windows 下 Git Bash：`bash.exe -c <command>`（路径可配置 + 探测默认安装位置；CreateProcess 层 cwd 用 Windows 路径形式）
- tokio::process：stdin `Stdio::null()`、stdout/stderr 分别 piped、`kill_on_drop(true)`
- 超时默认 120s、上限 600s；输出按字节捕获（1 MiB 上限）、中文 GBK 环境下 UTF-8 优先 lossy 解码
- chunked 输出实时发 `ToolCallOutputDelta`（TUI 增量渲染），结束后把 exit code + 时长 + 截断后的合并输出作为单条工具结果回填模型

### 存储与配置
- SQLite 表：`sessions(id, created_at, title)`、`messages(id, session_id, role, content, reasoning, tool_calls_json, created_at)`、压缩后历史替换即 UPDATE；TUI `/resume` 列出恢复
- config.toml：provider(base_url/protocol)、model、api_key 优先读 env（如 `DEEPSEEK_API_KEY`）、context_window、auto_compact_token_limit、shell 路径

### TUI（里程碑一范围）
- 对话区流式渲染正文与 reasoning（暗色折叠）、工具调用卡片（命令 + 实时输出 + exit code）、底部输入框
- 命令：`/new`、`/resume`、`/compact`（手动触发压缩，调试上下文管理的入口）、`/exit`

## 实施步骤
1. `cargo init` workspace + 各 crate 骨架 + trait/registry/event 类型定义（含 Skill/Hook/Permission 占位）
2. forge-storage：SQLx schema + repository（先于 core 收尾，session trait 需要）
3. forge-provider：chat/completions 协议面（SSE 流式 + usage + reasoning_content 解析），单协议先跑通
4. forge-core agent loop：历史管理 + token 估算 + 压缩器 + 事件广播，接 provider/storage
5. forge-tools：shell 工具
6. forge-tui：渲染 + 四命令
7. `/v1/messages`（Anthropic 格式）+ `/v1/responses` 两个协议面补齐
8. 集成验收：DeepSeek 真实 key 跑多轮会话（含触发压缩的场景）

## 验收标准（里程碑 1 完成 = ）
- `forge` 启动进入 TUI，能用国内模型 key 进行流式多轮对话，思维链实时折叠显示
- agent 能通过唯一 shell 工具执行命令完成任务（如"查看当前目录结构并总结"）
- 会话退出后 `/resume` 可恢复；长会话自动压缩触发后对话继续且历史正确收缩
- agent-core 不依赖任何 UI/HTTP 框架；新增一个协议面 Provider 只需实现 trait + 注册，不改 loop
